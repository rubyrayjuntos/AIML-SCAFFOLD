# AIML-SCAFFOLD

Azure-first platform for generating governed ML project repositories. The R1 factory accepts a product manifest and deterministically generates an Azure ML batch project with Terraform infrastructure, training, evaluation, conditional registration, explicit-version batch serving, and project-local evidence.

This repository is intentionally independent of the previous churn prototype. It does not import its code, data, schemas, model registry, or deployment state.

## R1 factory

```bash
aiml-scaffold validate examples/manifests/r1-ml-batch.yaml --allow-experimental
aiml-scaffold plan examples/manifests/r1-ml-batch.yaml --environment dev --allow-experimental
aiml-scaffold generate examples/manifests/r1-ml-batch.yaml --output /tmp/example-risk --allow-experimental
aiml-scaffold doctor /tmp/example-risk --environment dev --no-cloud
```

The generated lifecycle is:

`provision → train → evaluate → conditionally register → deploy explicit model version → invoke batch endpoint → emit evidence`

Terraform is the sole generated Azure IaC provider for R1. Existing Bicep, Databricks, Foundry, Search, online serving, monitoring, and retraining assets remain reference or future-release work and are not generated by R1. Bicep must never target a Terraform-owned R1 environment.

Generated provenance is explicit: `platform/source-manifest.yaml` preserves normalized user intent, `platform/resolved-plan.json` explains every applied decision, and `generation-receipt.json` verifies those artifacts, pinned constraints, templates, and the generated tree. Validation and planning report release status, capability maturity, policy, CLI override use, authorization, and the remaining live-evidence boundary.

The manifest declares Azure tenant and deployment subscription independently from the Terraform backend subscription. Cross-subscription state is rejected unless policy explicitly permits it. `doctor` verifies generation integrity before any read-only Azure query, then reports context, active versus intended identity, backend management/data planes, OIDC configuration, scoped RBAC, SKU, and quota separately. It never represents GitHub token exchange or Terraform state writes as locally proven.

## Acceptance boundary

Local tests and static infrastructure validation do not prove a deployed system. R1 live acceptance is Dev-only and requires a separately approved clean-room Azure run without source repair. Test and Prod remain unvalidated until independently evidenced.

## Churn scenario

The scenario uses the canonical 7,043-record Telco Customer Churn corpus. The source is downloaded by the Databricks ingestion task and validated before any downstream table or model is produced. No synthetic customers are part of the scenario.

## Status

The contract kernel, deterministic generator, Terraform/Azure ML batch template, and local evidence implementation are present. No CLI command deploys resources. Live Dev acceptance, package publication, and release publication remain explicit operator actions.
